## 维护约定

1. **改功能 = 改文档**：功能行为变了，同一次改动里更新对应章的相关小节，并刷新章头的「最后核对」日期与基线 commit。只改实现不改行为的重构不用动文档（锚点失效除外）。
2. **只写现状**：文档里不留「计划」「TODO」「即将」。历史上的取舍写进各章「设计决策与已知坑」，且只保留仍在影响现状的。
3. **锚点用 文件+符号**（函数/类型名），不用行号。
4. **新功能**：归入最相关的章；确实是新领域再开新章，并在本索引登记。
5. **不确定就标注**：写不准的行为标 `⚠️待核对`，宁缺毋滥——错误的现状描述比没有更危险。
6. 每章模板：定位 / 入口与展示面 / 行为规格 / 设置项 / 与其它功能的交互 / 数据与文件 / 代码锚点 / 设计决策与已知坑。
