# 繁体中文（zh-Hant）文案规范

> 2026-09-03 加繁体界面时定下。给所有往 `Localizable.xcstrings` 加文案的人（含 AI 会话）看：
> **每个新键必须同时写 en 和 zh-Hant**，繁体按这份规范写，不是把简体做字级转换。
> 缺任何一种语言，`generate-strings.py`、`scripts/check_strings_parity.py` 和 selftest 的本地化守卫都会红。

## 取向

- 目标读者是台湾 macOS 用户。用词以 **Apple 自己的 macOS 繁体界面**为准（本机 `/System` 下的
  `.loctable` 里能直接读到 Apple 的 zh_CN ↔ zh_TW 对照，拿不准就去查），Apple 没有的按台湾常用软件用语。
- 语言名保持各自写法：简体中文 / 繁體中文 / English，三档界面下都不翻译。
- 品牌名保持原文（Server酱、Apple Music、QQ 音乐→QQ 音樂 这类通用转换可以，专有名不硬改）。
- URL、锚点、代码、路径一字不动：`…lyrimuse#网页端` 转成繁体链接就失效。
- 标点用全形（，。；：？！「」），简体原文里的半角逗号/问号在繁体版顺手改成全形。

## 字级细节（ICU 转换会漏的）

- 「里」作方位一律「裡」（設定裡、App 裡）；公里 / 里程除外。
- 周（星期）一律「週」：兩週、每週、12 週、週報；周圍、四周不改。
- 「啓」是台湾不用的异体，写「啟」。「向导」不是「嚮導」，写「設定引導」或「精靈」。
- 一并→一併，抵消→抵銷，省略号→刪節號，年历→年曆，标注→標註，发布→發佈。

## 加文案的流程

1. 在 `Localizable.xcstrings` 里同一次写全：键（简体原文）、`en`、`zh-Hant`，占位符（`%@` / `%1$@` / `%d`）
   三语一致。
2. `python3 Localization/generate-strings.py`，把三份 `.strings` 一起提交。
3. `python3 scripts/check_strings_parity.py`；`swift run lyrimuse-selftest --filter contracts -q`。
