隐私政策

最后更新：2026 年 9 月 8 日

一句话版：Lyrimuse 没有账号体系、没有遥测、没有统计。关于你和你听什么，没有任何信息会被发送到开发者的服务器。App 确实会联系第三方服务，因为歌词得从别人那里找，本页把它们全部列出来。

1. 适用范围

本政策适用于 Lyrimuse macOS 应用及其随附的后台采集服务，以及 yudaotor.github.io/lyrimuse 这个网站。Lyrimuse 是一个由个人开发者（Yudaotor）维护的免费开源项目，背后没有公司。

2. 我们收集什么：什么都不收

没有注册、没有用户 ID、没有崩溃上报、没有使用统计。开发者不运营任何接收 App 数据的服务器，因此手上没有任何关于你的数据。也就没有什么可以给你导出、更正或删除的——因为从来没有采集过。

源代码是公开的，所以这件事你可以自己去核，不必只听我说。

3. 留在你自己 Mac 上的东西

App 记住的一切都写在你自己的机器上，主要在 ~/.config/lyrimuse 下：

  • 你的设置
  • 歌词缓存（所以听过一次的歌离线也能显示）
  • 本机听歌历史，榜单和「那年今日」就是从它算出来的
  • 你主动连接的服务的凭据，比如 Last.fm 的 session key 或 ListenBrainz 的 token

这些都不会上传到任何地方。删掉 App 就没了；随附的 uninstall.sh --purge 会把它们彻底删除。

4. App 会联系哪些服务器

找歌词就得去问有歌词的人。一首歌开始播放时，它的歌名、歌手、专辑和时长会被发给歌词源用于查询。这些查询不会附带任何能标识你或你这台机器的信息。

正常使用时始终会发生

歌词查询网易云音乐、QQ 音乐、酷狗、酷我、咪咕、Musixmatch、LRCLIB、YouTube Music（LyricFind），以及托管在 GitHub 上的 AMLL 歌词库

「关于」页显示的 star 数GitHub API

只有你自己打开之后才会发生

以下功能默认关闭，你不去连它就一直不会联网：

功能联系的服务
听歌打卡（scrobble）你连接了账号才会用到的 Last.fm 和／或 ListenBrainz。上送的是播放器报告的曲目信息，原样不动。
在线翻译兜底翻译默认走 Apple 的设备端翻译框架，歌词不出本机。只有设备端处理不了某个语种组合时，才会退到在线兜底（MyMemory）。
每周听歌小结推送你自己配置的那个推送平台：Bark、钉钉、企业微信、Discord、飞书或 Server酱。
可分享的「正在听」网页你自己配置的地址。如果你部署了自己的 Cloudflare Worker，那个地址是你的，开发者看不到。

上述第三方各自有自己的隐私政策和日志策略，不在开发者的控制范围内。另外，联系任何网络服务都必然会让对方看到你的 IP 地址，这跟你访问一个网站是一回事。

5. 对外请求日志

App 发出的每一次网络请求都会记进你本机的系统日志。这些日志行的设计是从源头就安全，而不是记完整信息再指望事后脱敏：它只记录服务名、操作、域名、HTTP 状态码和耗时，从不记录完整 URL、请求头、请求体、响应体或任何凭据。

你可以自己在「控制台」里看这些日志，也可以在设置里导出一份已脱敏的诊断信息。导出永远是你手动触发的动作，导出的文件放在哪儿由你决定，不会自己发去任何地方。

6. App 申请的权限

如果你选择 Apple Music 作为播放器，macOS 会要求你授权对 Music.app 的「自动化」访问，这是读取正在播放什么的方式。其它播放器走系统级 Now Playing 接口，完全不需要权限。这些权限只用于跟随播放，没有别的用途。

7. 这个网站

这些页面是托管在 GitHub Pages 上的静态文件，没有 cookie、没有统计脚本、没有任何追踪。GitHub 作为托管方会像任何 Web 服务器一样记录请求，详见 GitHub 的隐私声明。

8. 未成年人

Lyrimuse 不面向儿童，并且不收集任何年龄段任何人的个人数据。

9. 变更

如果 App 的数据行为发生变化，本页会跟着改，顶部日期也会更新。本页的修改历史在仓库里是公开的，你可以看到具体改了什么、什么时候改的。

10. 联系方式

有疑问或发现错误：在 GitHub 上提 issue。
